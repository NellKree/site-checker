# Срез

Экспериментальный MVP сервиса независимой проверки сайтов перед приёмкой. Один React-проект объединяет галерею и шесть самостоятельных дизайн-концепций с общей логикой проверки.

## Технологии

React, Vite, JavaScript, обычный CSS и Google PageSpeed Insights API v5. Для локальной разработки нужен Node.js 22.12+ или 20.19+. Публикация выполняется через GitHub Actions на GitHub Pages.

## Установка и запуск

```sh
npm ci
npm run dev
```

Vite выводит адрес локального сервера. На главной странице откройте концепцию, введите адрес сайта и нажмите «Проверить сайт». Переключатель в шапке позволяет сравнить интерфейсы. Введённый адрес и отчёт сохраняются при переключении в одной вкладке.

## Демо и реальная проверка

В деморежиме используется один синтетический пример ответа PageSpeed из `src/data/demo-report.json`. Он встроен в JavaScript-сборку и доступен без сети после загрузки приложения. Отчёт явно помечен как демонстрационный и всегда относится к example.com, независимо от введённого адреса.

В реальном режиме браузер отправляет запрос непосредственно в Google PageSpeed Insights API без API-ключа. Доступны мобильный и настольный профили. Запрашиваются Performance, Accessibility, Best Practices и SEO. Интерфейс отображает исходные оценки Lighthouse, основные метрики, рекомендации и доступные данные реальных пользователей.

Google может ограничить запросы без ключа. При исчерпании квоты, недоступности страницы, сетевой ошибке или превышении времени ожидания показывается соответствующее сообщение. Демо выбирается пользователем отдельно. [Документация PageSpeed](https://developers.google.com/speed/docs/insights/v5/get-started).

## Структура

- `src/designs/` — отдельные компоненты и CSS для Minimal, Laboratory, Desktop, Editorial, Experimental и Premium.
- `src/components/` — галерея, форма проверки, элементы отчёта и демонстрационные предложения услуг.
- `src/services/pagespeed.js` — проверка URL, обращение к API и обработка ошибок.
- `src/data/reportMapping.js` — общая обработка ответа PageSpeed.
- `src/data/demo-report.json` — сохранённый демонстрационный отчёт.
- `public/` — локальные статические ресурсы.
- `.github/workflows/pages.yml` — автоматическая сборка и публикация.

## Сборка

```sh
npm run build
npm run preview
```

Готовый статический сайт находится в `dist/`. В репозиторий включены исходники и `package-lock.json`. Каталоги `node_modules/`, `dist/`, временные файлы и `.env*` исключены через `.gitignore`.

## GitHub Pages

В настройках репозитория **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**.

Workflow **Publish to GitHub Pages** запускается при каждом push в `main`. Также доступен ручной запуск из **Actions**. Он выполняет `npm ci`, `npm run build` и публикует `dist/` официальными GitHub Actions. Разрешения ограничены чтением исходников и публикацией Pages.

Vite использует относительную базу `./`, а страницы концепций используют hash-маршруты. Поэтому одна сборка поддерживает адрес `/site-checker/` и корень собственного домена. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Собственный домен задаётся в настройках Pages после проверки существующих DNS-записей и подтверждения владельца. Для публикации через GitHub Actions файл CNAME в исходниках не требуется. [Настройка домена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Ограничения MVP

Автоматическая проверка использует показатели и рекомендации PageSpeed. Собственная методология оценки и анализ технического задания пока отсутствуют. Полный отчёт за 3 990 ₽ представлен сообщением «Скоро появится». Форма экспертного аудита демонстрационная, введённые данные остаются в форме. Оплата, загрузка файлов, сервер, база данных и авторизация пользователей в этой версии отсутствуют.
